# デモ用の仮ストーリー

画面のスクリーンショット撮影や動作確認のために、**各ステージの問いに対する回答をあらかじめ用意したもの。**
そのままコピーして入力欄に貼れる。

**最終更新: 2026-09-23 / 対象: `PROMPT_VERSION = "v2"`**

> これは著者が作成した**架空の回答**であり、実際の参加者データではない。
> この台本で撮った画面を論文に載せる場合、図表キャプションにその旨を明記すること。

---

## 場面設定

チーム開発型 PBL の中間発表当日。

- 自分の担当分は前日に仕上げ、当日の朝は発表練習に充てられた
- 同じチームのメンバーの担当分が朝になっても提出されなかった
- 本人に何も言わず、自分でスライドを作り直して発表30分前に事後報告した
- 結果として発表は成立したが、チームの空気が悪くなった

**この場面を選んだ理由** — 他責的な問題認識（メンバーが期限を守らない）から、
自分ごとの課題（不安を抱え込んで先回りする）への転換が自然に起きる構造になっている。
6ステージが空回りせず、どのステージにも答えることがある。

対話版と KWS 版で同じ場面を使う。**条件間で内容が揃うので、2つの画面を並べた図にできる。**

---

## 対話版　`/`　での台本

AI の問いは、1番目と6番目が固定文言で常に同じ。2〜5番目は生成なので**表示される文面は毎回少し変わる**。
下に載せた生成文は想定例で、実際の画面と一字一句は一致しない。

### 1　Keep　良かったこと

> **AI（固定文言）**
> 今日のPBL活動、おつかれさまでした。この時間は、あなたの中にあるものを一緒に言葉にしていく時間です。まずは、うまくいったこと・続けたいと思ったことから聞かせてください。

```
今日は中間発表のスライドが一通り形になりました。自分が担当した分は前日に作り終えていたので、当日の朝は落ち着いて練習に回せました。早めに動くのは続けたいです。
```

### 2　Problem　気になったこと

> **AI（生成・想定例）**
> 前日までに仕上げて当日を練習に使えたのは、見通しを持って動けた証拠ですね。一方で、今日の活動の中で引っかかったことやモヤモヤしたことがあれば、聞かせてもらえますか。

```
同じチームのメンバーの担当分が当日の朝になっても出てこなくて、結局わたしが作り直しました。前から何度も期限は共有していたのに、毎回こうなるのが正直しんどいです。
```

### 3　Fact　事実

> **AI（生成・想定例）**
> 何度も期限を共有してきたのに、また同じことが起きたのですね。しんどいと感じるのは自然だと思います。その朝のことですが、担当分が出てこないと分かってから、あなたは実際にどう動きましたか。

```
8時ごろにSlackを見て、まだ上がっていないと気づきました。本人には何も言わずに、自分でスライドを3枚作り直しました。発表30分前に「こっちで作ったから」とだけ送りました。
```

### 4　Feeling_Other　相手の視点

> **AI（生成・想定例）**
> 本人に確認する前にご自身で作り直して、直前に結果だけを伝えたのですね。そのとき相手の側に立ってみると、あなたのその行動は相手の目にはどのように映っていたと思いますか。

```
…たぶん、信用されてないと思ったかもしれません。相談もなく勝手に作り替えられたら、自分なら嫌です。あとで「ごめん」とだけ返ってきたのが、今思うと気まずかったんだと思います。
```

### 5　Essence　本当の願い

> **AI（生成・想定例）**
> 相手の側から見ると、相談なく引き取られたように映ったかもしれない、と。そこに気づけたのは大きいと思います。では、その朝の場面で、あなた自身は本当はどうしたかったのでしょうか。

```
本当は、一緒に間に合わせたかったんだと思います。発表を失敗したくなかったし、でもそれ以上に、あの人が抜けた状態でチームとして出すのが嫌でした。手伝おうか、って一言聞けばよかった。
```

### 6　Closing_Insight　本当の課題

> **AI（固定文言）**
> ここまでの対話、ありがとうございました。最後にひとつお聞きします。今日の対話を通して、あなた自身が主体的に向き合うべき『本当の課題』は何だと改めて思いましたか？

```
メンバーが期限を守らないことが問題だと思っていましたが、たぶん本当の課題は、わたしが「間に合わないかも」と不安になった時点で、それを相手に言わずに抱え込んで先回りしてしまうことです。手を動かす前に一言聞く、それができていません。
```

この回答を送ると入力欄が閉じ、「行動計画（Try）へ進む」が出る。

## KWS フォーム版　`/kws`　での台本

統制条件。先に Keep / Problem をフォームに入力してから対話に入る。
**Problem は必須**で、空だと送信できない。

### 開始フォーム

**良かったこと（Keep）**

```
中間発表のスライドが一通り形になりました。自分の担当分は前日に作り終えていたので、当日の朝は練習に回せました。
```

**問題点・モヤモヤ（Problem）**

```
同じチームのメンバーの担当分が当日の朝になっても出てこなくて、結局わたしが作り直しました。前から何度も期限は共有していたのに、毎回こうなるのが正直しんどいです。
```

### Turn 1 への回答

AI は事実や自身の感情を確認する問いを返す。

```
8時ごろにSlackを見て、まだ上がっていないと気づきました。本人には何も言わずに、自分でスライドを3枚作り直して、発表30分前に「こっちで作ったから」とだけ送りました。
```

### Turn 2 への回答

AI は相手の視点に気づかせる問いを返す。

```
たぶん、信用されてないと思ったかもしれません。相談もなく勝手に作り替えられたら、自分なら嫌です。
```

### Turn 3 への回答

AI は次に向かう欲求や意思を引き出す問いを返す。

```
本当は一緒に間に合わせたかったんだと思います。手伝おうか、って一言聞けばよかった。次からは抱え込む前に声をかけます。
```

ここで `turnCount` が 3 に達し、「行動計画（Try）へ進む」が出る。

> **統制条件には `Closing_Insight` にあたるターンが無い。**
> 対話版で主要データになる「本人が言語化した本当の課題」が、統制条件では収集されない。
> これは設計上の差であり、台本の不足ではない。

## メモ欄の内容

両条件とも同じものを使う。メモは**発言を送信したときにサーバーへ保存される**ので、
対話を始める前に入れておくこと。Try 生成時にもこの内容が参照される。

```
・朝の時点で声をかけられなかった
・自分でやったほうが早い、と思ってしまう
・次は「手伝おうか」を先に言う
```

## 撮影時の注意

| 項目 | 対処 |
|---|---|
| 開発用インジケータ | `next.config.ts` の `devIndicators: false` で消してある |
| メールアドレスの写り込み | 画面右上に出る。論文に載せるならトリミングするか、撮影用のアカウントを使う |
| 画面幅 | **1280px 以上**で撮る。1024px 未満だとメモ欄が右ではなく下に回り込み、2ペイン構成が写らない |
| 撮る場面 | 開始前画面／対話の途中／Try 表示後 の3枚あれば十分 |

所要時間の目安は、貼り付けだけなら AI の応答待ちを含めて5分程度。
