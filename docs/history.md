## 2026-08: 研究用に作り直す計画

旧 `docs/design.md` の計画。課題は3つ: データが残らない／入力が静的フォーム／対話の締めがない。

決めたこと:

- **書き込みはサーバー経由（Firebase Admin SDK）**。クライアントは Firestore に触らず、ルールは全面 deny。会話履歴の正本をサーバーに置き、改ざんできないようにする
- **Google ログイン**（Gmail・大学アドレスの両方を許可）。`sessions` には uid だけを置き、個人情報は `users` に分ける
- **AI 対話版を新設し、KWS フォーム版を統制群として残す**（`condition: "form" | "dialogue"`）
- 対話版は ALACT モデルに沿った6ステージ。Keep/Problem もフォームではなく対話で引き出す
- 締めの問いを固定文言にして、回答を主な測定データにする（v1 の文面:「今日の対話を通しての気づきや、どんな問題があると改めて思いましたか？」）
- 実装は「疎通確認 → 認証 → データ層 → UI」の4段階で、都度動作を確かめる

## 2026-09-09: プロンプト v2、ルートの入れ替え、Claude への移行

### プロンプト v1 → v2

添削を受けて、プロンプト内部の矛盾を解消した。

| 対象 | v1 | v2 | 理由 |
|---|---|---|---|
| 締めの問い | 「気づきや、どんな問題があると改めて思いましたか」 | 「あなた自身が主体的に向き合うべき『本当の課題』は何だと改めて思いましたか」 | 自己に向かう答えと外に向かう答えの二択を許すと、分析が「どちらを選んだか」を測ってしまう。自省への着地に一本化（※ v3 で改めた） |
| `feeling_other` | 自分の感情と相手からの見え方の両方 | 相手からの見え方のみ | 「問いは1つ」と矛盾していた。他責を崩す鍵の他者視点を残した |
| `essence` | 「出来事の表面ではなく」 | 「出来事の表面的な不満ではなく…（本質的な願いや目的）」 | 不満の吐き出しで止まらせない |
| Try | 「行動計画を出力」 | 新しい助言を足さず、本人の発話を再構成する | 対話中の助言禁止と矛盾していた |

あわせて、固定文言を `FIXED_MESSAGES` に集約し、版の切り替え口を `lib/prompts/index.ts` の1箇所にした。

このとき「深さによらず1ターンでステージが進む」設計は、統制群との比較と再現性のために**意図的に維持**した（「なるほど」の一言でもステージが終わる、という弱点は承知のうえ）。

統制群との差分は「単なる入力フォーム vs 対話的な足場かけ」と定式化した。KWS フォーム版の Turn 1〜3 の例文は対話版の `fact` / `feeling_other` / `essence` と同じにし、問いの中身を揃えて進行の構造だけを操作する、という立て方だった。

内省の分析に Kember et al. (2000) は使わないと決めた（原本が入手できず、文脈もずれるため）。代わりの候補として上田のリフレクションの4つの分類が挙がった。

### ルートの入れ替え

対話版を既定の体験にした。`/` = 対話版、`/kws` = KWS フォーム版、`/session` = `/` への転送。画面のステージ表示も「相手の視点」「本当の課題」に変えた。

### Gemini から Claude へ

- `gemini-2.5-flash` → `claude-sonnet-5`（公式 SDK、ストリーミングで受ける）。環境変数は `ANTHROPIC_API_KEY` / `CLAUDE_MODEL` / `CLAUDE_EFFORT`
- **temperature が使えなくなった**（Claude Sonnet 5 では廃止され、送ると 400）。Gemini 版の「低温度で問いの揺らぎを抑えている」という説明は使えなくなり、代わりに effort を記録する
- `sessions.temperature` → `sessions.effort`、`messages.usage` の項目名を変更。実データを取る前だったので互換は取っていない

## 2026-10-24: JSiSE 秋季研究会で発表

質疑:

- LLM なしで、自分で深掘りする力はつくか
- LLM は褒めるだけだが、社会に出たら褒められてばかりではない

- 授業直後より次回授業の冒頭に振り返るとよい（評価の都合上、扱わないことにした）

## 2026-10-27: 発表後の作り直し

### プロンプト v3

- **締めの問いを質問会議の「問題の再定義」に寄せた**:「ここまで問いに答えてきたことを通して、あらためて、いまの問題は何だと思いますか？」。v2 の文面は原因を自分に向けることを前提にしており、迎合と自責を促すおそれがあった（学会の質疑ともつながる）。画面の表示も「本当の課題」→「問題の言い直し」
- **進め方 B を追加**: 各ステージで「この話を続ける」「次の問いへ進む」を学習者が選ぶ（当初は1ステージ5ターンまで）。進め方 A（6ターン固定）と並べて開始画面で選ぶ
- システム名を「振り返りアシスト」に変更

### プロンプト v4

開発者自身が進め方 B で一周したところ、問いかけが崩れた。崩れ方と対処:

| 崩れ方（実例） | 対処 |
|---|---|
| 褒める・良い意味づけ（「気まずさを感じながらも最後まで居続けられた」「大きな発見ですね」） | 評価的な言葉と意味づけを禁止。受け止めは言い換え1文まで |
| 気持ちの推測・仮定の重ね（「もしそれが次に活かせる気づきだとしたら…」→「？？？？何を言ってるの？」） | 推測を禁止、問いは平易に短く |
| 直前の発言だけを追い、脇道（人前で画面を開きにくい）へずれる | 対象を Problem で挙がった問題の場面に固定 |
| 「覚えてない」「さっき話したやん」を受け止めず聞き直す。手の動きや作業ペースを聞く | 短い答えを受け止める。答え済みを聞かない。細部を聞かない |
| Keep で困ったことを話しても良い面を探させる | 「困ったことは次で聞く」と伝えて進める |
| Try が言っていない行動を足す、`**` が表示される | 3項目以内、言っていない行動を作らない、装飾なし |
| 相手の口調につられてくだけた口調になる | です・ます調で統一 |

ここまでをタグ `ver1` として保存した。

### プロンプト v5: ファシリテーター判断

v4 で足した規則（短い答えなら打ち切る、など）が問いの文面に混ざり、文脈を無視して発動した（「なにも」という意味のある答えで打ち切る等）。質問会議の役割分担に倣い、進行の判断（ALC）と問い（メンバー）を分けて LLM を2回呼ぶ形にした。

- 判断: 扱っている問題・話の状態（順調／学習者が自分から話を移した／それている／浅いまま）・聞けた観点・次に聞く観点
- 観点は ALACT モデル第2局面の問い（自分と相手それぞれの、したこと・考えたこと・感じたこと・望んだこと）をもとにした
- 判断を画面の「振り返りの進み方」に出す。学会の質疑「自分で深掘りする力」を受けて、振り返りの進め方そのものを持ち帰れるようにするため。テストのため `?debug=1` で判断の理由も出す
- 回数の上限を撤廃（上限で強制的に次へ移り、話の途中で観点が切り替わっていたため）。空欄でも次へ進めるようにした
- 空欄で進むと会話が assistant で終わり、今のモデルが 400 で拒否する不具合を修正

学習者役の LLM で試した結果、問いが判断どおりに出ないことがあった（「自分から動くという選択肢はどれくらい考えましたか」という質問の形をした助言）。答えを示唆する問いを禁止した。

### v5 を試して分かったこと（未解決）

開発者自身の試用で次の問題が出た。対応は [todo.md](./todo.md)。

- **観点を埋めにいく作りになった**。「居心地悪かった」に「いつ・どこで・誰と」、「自己重要感の欠如」「いっつも」に「ほかに話しておきたいことは」と、肝心の話を掘らない。画面に観点の一覧を出したことで「全部聞くなら ALACT をやらせるだけでいい。何が適応的なのか」が露わになった
- **進むかどうかを学習者に2つのボタンで選ばせるのは酷**。何も知らない人は「次の問いへ進む」を連打する
- 進行についての問い（「つながっていますか」）を使いすぎる。システムへの不満にまで聞く
- 英語で返す、LLM が「今日はここまでにしましょう」と勝手に終える

## 2026-10-29〜30: プロンプト v6（自動で次へ進む）

v5 の試用で出た問題（観点を埋めにいく、進むかどうかを学習者に選ばせる）を受けて、進め方 B を組み直した。設計の判断基準を「学習者が、自分を責めることなく、自分の関わりも含めて問題を言い直せるところまで連れていけるか」に置いた。

- 観点の一覧をやめ、ステージごとに「何が語られたら次へ進むか（ねらい）」を1つ置いた
- ファシリテーターがねらいへの到達を `not_yet` / `report` / `insight` で判定し、`insight` なら自動で次へ進む。丸山・森本が振り返りの記述を段階に分類して支援を変えたのにならった。進行を学習者でなくファシリテーターが持つのは、質問会議の ALC と問題提示者の分担に合わせたもの
- 判定は外れる前提で、学習者の「次の観点へ」（空欄でも可）と、ステージごとのターン数の目安を置いた（強制的には切らない）
- 学習者の言葉から「いちばん掘る価値のある話」を判断させ、それを手がかりに掘る
- 話のつながりを尋ねる問いは1つのステージで1回まで
- 画面のボタンを「送信」と「次の観点へ」にした。パネルは観点のチェックリストをやめ、扱っている問題・掘っている話・局面の説明を出す。上部の進行表示とパネルでステージの呼び名を揃えた
- LLM が対話を終える・進めることを口にするのを禁止した（「今日はここまでにしましょう」が出ていた）
- 学習者役の LLM で試し、事実で体の感覚を尋ねる・相手の視点で問題に関係のない人の事情を尋ねる、の2つが出たのでステージの注意に足した
